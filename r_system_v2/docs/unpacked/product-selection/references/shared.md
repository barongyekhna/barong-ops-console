# 双平台通用逻辑 + 小卖家门槛矩阵（references/shared.md）

本文件管三件事:(1) 小卖家"门槛矩阵"决策模型,(2) 通用红线,(3) "both 双平台"判据与战略流。
**both 产品要同时读 amazon.md 和 dtc.md。**

---

## 一、门槛矩阵（小卖家的核心决策模型）

用户的真实约束:**门槛太高做不起 / 门槛太低竞争激烈。** 把"门槛"拆成两个独立的轴:

```
                 资本/资质门槛(砌墙要花的钱和资源)
                 低 ───────────────────────► 高
   竞   低  │  ① 红海铺货区          ②  重资本壁垒区
   争   ▲   │     谁都能进,血战         认证/大MOQ/专利,
   门   │   │     【避开:门槛太低】       小卖家做不起
   槛   │   │                            【避开:门槛太高】
  (做的人  ├──────────────────────────────────────────
   多不多) │  ③ 技能执行区  ★目标★      ④  品牌锁定区
        高 │     靠差异化/listing/        大牌用预算+评论
            │     bundle/内容才能赢         锁死,打不穿
            │     【进:小卖家的缝】         【避开】
```

- **① 红海铺货区**:资本门槛低 + 竞争低门槛 → 人人能进,纯价格战。**避开**(用户说的"门槛太低竞争激烈")。
- **② 重资本壁垒区**:要认证/大额MOQ/高单价/专利 → **避开**(用户说的"门槛太高做不起")。
- **④ 品牌锁定区**:对手用钱(评论+广告+供应链)锁死 → 打不穿,**避开**。
- **③ 技能执行区 ★**:护城河是"活儿"砌的 —— 差异化设计、更好的 listing、聪明的 bundle、
  精准细分人群、更强的内容/广告创意。**挡得住懒人和铺货党,挡不住有能力的小团队。这就是要进的象限。**

**判断口诀:护城河是用"钱"砌的还是用"活儿"砌的?**
钱砌的(认证/MOQ/专利/广告预算/评论数海量)→ 减分或剔除;活儿砌的 → 加分,这是你的主场。

## 二、通用红线（任一平台命中即剔除）

无论亚马逊还是独立站,这些直接 0 分:

- **锂电池 / 含电池**:运输、合规、平台限制全是坑。
- **液体 / 膏体 / 易漏 / 危险品**:头程、仓储、退货成本高。
- **易碎 + 重**:运费和破损率双杀,看着 60% 毛利能被打到 40%。
- **侵权风险**:仿外观、仿品牌、专利密集区 —— 一封投诉就清零。
- **强制认证**:FDA / 医疗器械 / 儿童安全 / 电气强制认证等 —— 资本门槛,小卖家扛不动。
- **大额 MOQ / 高单价**:首单压太多现金,试错成本高,周转慢。
- **强季节性**:80% 营收挤在 90 天窗口 → 淡季储仓费 + 现金压库存。
- **viral 待证伪**:无 12 个月历史的暴涨,默认短命。

## 三、"both 双平台"判据

一个品判为 both,需要**同时**:
- 亚马逊侧:有现成自然搜索需求 + 评论壁垒可破 + 利润扛得住 FBA(满足 amazon.md)。
- 独立站侧:有 3 秒钩子/情绪价值 + 毛利 ≥60% 付得起广告 + 有复购/bundle 空间(满足 dtc.md)。
- 且**不冲突**:不是"亚马逊已价格战商品化"那种(那种只能独立站避开亚马逊)。

both 类是最优质的种子,评分中应加权。

## 四、战略流（优先识别,直接服务用户的 pivot）

用户的长期路线是 **从亚马逊向独立站迁移**。判断时优先识别符合这条流的品:

```
亚马逊 = 验证机 + 现金流引擎
  · 用现成搜索需求,低成本快速验证"这品到底有没有人买"
  · 跑出真实销量/退货/利润数据(这是任何选品工具都没有的真数据)
        │  赢家(数据验证过的)
        ▼
独立站 = 毛利 + 资产 + 品牌
  · 把验证过的赢家迁/扩到独立站
  · 拿回更高毛利、客户数据(first-party)、品牌资产、定价权
  · 摆脱平台的费用/审计/价格压缩/账期
```

**因此**:一个"能在亚马逊低成本验证、且之后有独立站升级空间(有钩子/毛利/品牌故事)"的品,
应在评分中**显著加权** —— 它同时喂饱短期现金流和长期资产,正是这套打法要找的种子品。

判路由时:这类先标 `amazon`(验证阶段),并在建议里标注 `dtc_migration_candidate: true`,
等亚马逊跑出正向数据后再触发独立站扩张。

### ★ Keepa × Serper:发现"迁移种子"的具体方法

把上面的战略流变成可执行的发现动作:**库里 Amazon 需求强(BSR/销量已验证)的产品,
手动用 Serper 查它的 Google SERP —— 如果页一弱(论坛/薄内容占位、无强 DTC 品牌),
就是"需求已验证 + 独立站 SEO 能排进去"的迁移种子。** 这类同时是最强的 `dtc_migration_candidate`,
也是 dtc_seo 路由的首选。逻辑细节见 `dtc_data.md` 与 `ARCHITECTURE.md §6.7`。
