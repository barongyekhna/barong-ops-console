# 跨境选品判断手册（小卖家版）

本技能是**给 AI 用的判断手册**:初筛模型（GPT / DeepSeek）和终筛模型（Opus）都加载它,
对每个候选产品输出 `保留 / 剔除 / 待定` + 评分 + 理由 + 差异化建议。
亚马逊和独立站是**两套不同的经济学**,不能用一套标准。详细分轨规则在 `references/` 下:

- `references/amazon.md` —— 亚马逊 FBA 选品准则（吃自然搜索流量,赢在自然位 + 评论壁垒）
- `references/dtc.md` —— 独立站 DTC 选品准则（两条子路:广告品 + SEO 品,经济学不同）
- `references/dtc_data.md` —— 独立站数据源（广告库 API / Serper SEO / Keepa×Serper 交叉）
- `references/shared.md` —— 双平台通用逻辑 + 小卖家"门槛矩阵"红线
- 实现细节(数据库/工作流/prompt schema/部署)见 `ARCHITECTURE.md`

**判断任一产品前,先读对应分轨文件,再回到本文件的评分卡与路由逻辑。**

## 一、核心哲学（所有判断的底层）

### 1. 小卖家的命门:要"技能门槛",不要"资本门槛"

用户的痛点是:**门槛太高的做不起,门槛太低的竞争太激烈。** 这不是矛盾,是要找到正确的门槛**种类**:

- **资本/资质门槛**(避开):大额 MOQ、认证重(FDA / 医疗 / 锂电 / CE 强制)、单价高、专利密、
  品牌已锁死的类目。这些门槛是用钱和资源砌的,小卖家砌不起 —— **避开**。
- **技能/执行门槛**(目标):靠差异化设计、更好的 listing、聪明的 bundle、精准的细分人群、
  更好的内容/广告创意才能拿下的品。这种门槛挡得住懒人和铺货党,但挡不住一个有能力的小团队。
  **这就是小卖家能挤进去的那道缝。**

判断时永远问一句:**这个品的护城河是用"钱"砌的还是用"活儿"砌的?** 前者剔除,后者是候选。

### 2. 反爆品陷阱(viral trap)

30 天暴涨的销量/排名 **不等于** 真实需求。TikTok 带火的品,需求常在 60–90 天内崩塌。
**永远看 12 个月趋势,不看 30 天快照。** Keepa 的 BSR / 价格历史就是你识别这个的核武器 ——
如果一个品 3 个月前突然起量、之前毫无历史,默认按"viral 待证伪"处理,不要进货。

### 3. 两平台一句话区分

- **亚马逊**:需求是**现成的**(人已经在搜),你赢在抢自然位、突破评论壁垒、改进 listing。
- **独立站**:需求是**你造的**(投广告教育用户),你赢在毛利够付流量、产品有 3 秒钩子、能复购。

同一个品在两个平台的判断标准可能完全相反:亚马逊嫌"太普通"的品,独立站可能因为有故事/钩子而能做;
独立站嫌"毛利太薄付不起广告"的品,亚马逊可能因为有稳定搜索而能做。

## 二、系统架构(完整选品流水线)

设计原则:**漏斗 + 成本纪律**。越往后越贵的资源(Opus、人工)处理越少的候选。
绝不让 AI 去看规则就能毙掉的垃圾。

```
[Stage 0] 候选发现 Discovery
   亚马逊轨: Keepa Product Finder(按类目/BSR区间/价格带/评论数粗筛) + 类目 Best Sellers
   独立站·广告子路: Meta Ad Library API(有人持续投=已验证) + Google Trends
   独立站·SEO子路: Serper(手动触发,查 Keepa 已入库产品的 Google SERP 弱点) + Keepa×Serper 交叉
   产出: 候选 ASIN / 产品池(每天数千)
        │
        ▼
[Stage 1] 数据富化 Enrichment   —— Keepa product query,1 token/个,节流 20/min
   拉全量: BSR历史 / 价格历史 / 价格地板走势 / offer数 / 卖家数 / review velocity / 类目
        │
        ▼
[Stage 2] 规则预筛 Rule Pre-filter   —— 纯代码,0 AI 成本,这一关砍掉 70–90%
   硬性 kill(命中任一即毙,不进 AI):
     · 价格不在目标带  · 毛利/加价倍数不达标  · 价格地板12个月持续下滑(价格战)
     · 单一品牌份额过高(类目锁死)  · 卖家数过多(>15, 红海)  · 评论壁垒过高
     · 重量/易碎/锂电/液体/认证/侵权红线(见 shared.md)  · viral待证伪(无12月历史)
        │
        ▼
[Stage 3] AI 第一层 · DeepSeek(量化过滤器,走量,便宜)
   只吃结构化 Keepa 字段,做规则写不出的模糊量化判断(竞争可攻性/需求质量)
   输出 0-100 粗评 + keep/cut/hold;放行前 X% 进第二层
        │
        ▼
[Stage 4] AI 第二层 · GPT(带上下文验证)
   读真实 listing/差评/竞品广告,验证数字真伪 + 找差异化缺口
   输出 验证评分 + 差异化缺口 + 红旗
        │
        ▼
[Stage 5] AI 第三层 · Opus(决策 + 方案,只看最后几十个)
   护城河是钱砌还是活儿砌 / 方案以小卖家资源可行性 / 真实 P&L / 平台路由
   输出 终评分 + 路由 + 差异化方案 + 风险 + 行动建议
        │
        ▼
[Stage 6] 输出与分流
   入库(PostgreSQL),按路由打标签: Amazon / 独立站 / both
   Top 候选推 Telegram/WeCom,人工最终过目后才进入打样/采购
```

**成本纪律的数量级示例**(每天):
发现 ~5,000 → 富化 ~5,000(5,000 token,约 4 小时滴流)→ 规则预筛后剩 ~800 →
DeepSeek 后剩 ~150 → GPT 后剩 ~40 → Opus ~40 → 人工看 Top 10–20。
Opus 每天只碰几十个,成本可控;Keepa token 也在 20/min 流速内。

### ops-console 落地要点

- **滴流不爆发**:富化用每分钟触发的定时作业,每次取 ~20 个,匹配 Keepa 20/min 回血,
  用 `time_to_refill` 等待,别整点大批量(会撞 60 分钟 token 上限 + 限流)。
- **状态机入库**:每个候选一行,带 `stage`(discovered/enriched/rule_passed/ai1_passed/final/rejected),
  失败可重入,不重复消耗 token。
- **去重**:发现层对 ASIN/产品指纹去重,别反复富化同一个。
- **模型分层调用**:Stage 3 走 DeepSeek/GPT(便宜),Stage 4 走 Opus(贵),严格不越级。
- **预筛前置**:能写成代码规则的判断,绝不交给 AI —— 既省钱又稳定(规则不会幻觉)。

## 三、AI 三层分工(各答一个不同的问题,不共享标准)

三层不是同一标准跑三遍,而是**同一个产品被问三个不同的问题**,组成漏斗:

### 第一层 · DeepSeek(量化过滤器)——"值不值得花更贵算力细看?"
- 只吃**结构化 Keepa 字段**,做规则写不出、但不值得动贵模型的**模糊量化判断**。
- 例:把 BSR 走势形状 + 评论增速 + 卖家数 + 价格地板揉一起,读出"竞争能不能攻"。
- 走量、便宜、宁可错放不可错杀;拿不准给 `hold` 放行。
- 输出:`{ "score":0-100, "verdict":"keep/cut/hold", "competition_attackability":0-100, "demand_quality":0-100, "top_reason":"一句话", "channel_guess":"amazon/dtc/both" }`
- **不做任何创意/质化判断。**

### 第二层 · GPT(带上下文验证)——"数字背后是真的吗?有真的差异化缺口吗?"
- 读 DeepSeek 够不到的**真实内容**:listing 标题/主图/bullet、集中差评、(独立站)竞品广告文案。
- 验证数字没骗人(BSR 好看但 listing 烂?差评里有反复出现的可改痛点?viral 假需求?)。
- 输出:`{ "validated_score":0-100, "verdict":"keep/cut/hold", "differentiation_gap":"文本", "demand_real":true/false, "red_flags":[...], "channel_guess":"amazon/dtc/both" }`

### 第三层 · Opus(决策 + 方案)——"我这个小卖家该不该下注,怎么下?"
- 只看最后几十个,做**赌错就亏钱**的判断:
  护城河是钱砌还是活儿砌 / 差异化方案以小卖家资源是否真可行 /
  退货率×运费×储仓费的真实 P&L / 平台路由 / 行动方案。
- 输出:`{ "final_score":0-100, "verdict":"keep/cut/hold", "channel":"amazon/dtc/both", "barrier_type":"capital/skill", "differentiation_plan":"文本", "pnl_estimate":{...}, "risks":[...], "next_action":"文本", "dtc_migration_candidate":true/false }`

> 严格不越级:任一产品必须 DeepSeek→GPT→Opus 顺序通过,绝不跳层,绝不让 Opus 碰未经前两层过滤的候选。

## 四、统一评分卡(0–100)

每条分轨文件给出该平台的**权重与阈值**,本卡是骨架。低于 **60 直接剔除**,60–75 待定,75+ 保留。

| 维度 | 说明 | 亚马逊权重 | 独立站权重 |
|---|---|---|---|
| 需求真实性 | 12月趋势稳定/增长,非viral | 高 | 高 |
| 利润结构 | 净利/毛利达标,扛得住费用波动 | 高 | **最高**(付费流量生死线) |
| 竞争可攻性 | 评论/卖家/品牌份额/新品占比 | **最高** | 中 |
| 门槛种类 | 技能门槛(加分)vs 资本门槛(减分) | 高 | 高 |
| 差异化钩子 | 能改进的弱点 / 3秒视觉钩子 | 中 | **最高**(没钩子无法投放) |
| 复购/AOV | 消耗品/订阅/bundle 潜力 | 中 | 高(摊薄CAC) |
| 履约友好 | 轻/不易碎/低退货/无红线 | 高 | 高 |

**任一硬红线命中 = 直接 0 分剔除**,不进加权(见各分轨 kill list 与 shared.md 红线)。

## 五、路由逻辑(Amazon / 独立站 / both)

终筛阶段对每个保留品判定主战场:

- **判 Amazon**:有稳定自然搜索需求 + 评论壁垒可破 + 利润扛得住 FBA 费用,
  但**缺独立站需要的 3 秒钩子/故事**(太"功能性、不性感")→ 走亚马逊。
- **判独立站**:有强视觉钩子/情绪价值/可demo + 毛利 ≥60% 付得起广告 + 有复购或bundle空间,
  但在亚马逊已被**商品化/价格战**(价格地板下滑)→ 走独立站,避开亚马逊红海。
- **判 both**:同时满足"亚马逊有现成需求" + "独立站有可投放钩子且毛利够" → 双平台。
  这类是最优质的种子。

**战略流(用户的 pivot,judging 时优先识别此类)**:
理想路径是 **亚马逊先验证需求 + 跑现金流 → 赢家迁/扩到独立站拿毛利 + 客户数据 + 品牌**。
所以一个"先能在亚马逊低成本验证、之后有独立站升级空间"的品,应在评分中加权 ——
它同时喂饱短期现金流和长期资产。

## 使用提醒

1. 判断任何产品**先读对应 `references/` 分轨文件**(both 则两个都读 + shared.md)。
2. 硬红线优先于一切加权 —— 命中即剔除。
3. 区分门槛种类是这套手册的灵魂:资本门槛减分,技能门槛加分。
4. 一切需求判断以 **12 个月趋势**为准,警惕 viral 陷阱。
