# 空地基任务序列

## 1. 命名规则

后续对话、计划、Codex 任务、验收记录和 CHANGELOG 必须使用“`Fxx：名称`”完整标识，不再只说“任务 4”“任务 5”或其他容易与历史编号混淆的简称。

任务代号一旦固定，不因插入讨论、审查或返工而重编号。返工应继续引用原 Fxx，并明确修订范围。

## 2. 固定任务

| 代号 | 名称 | 目标边界 |
| --- | --- | --- |
| F04 | 工程文档拆分 | 将 V1.1 蓝图拆分为架构、模块、API、数据、认证、n8n、任务和施工规则文档。 |
| F05 | 后端空骨架 | 建立 FastAPI / Python 空骨架和 `/health`，不接真实业务。 |
| F06 | 数据库迁移骨架 | 建立 PostgreSQL / Alembic 迁移机制，不提前实现业务模块。 |
| F07 | 核心空地基表 | 按已审查 schema 创建核心基础表。 |
| F08 | 认证基础 | 实现 owner 初始化、登录、退出、当前用户和访问保护。 |
| F09 | 前端空壳与登录页 | 建立 Next.js / React / TypeScript 空壳、`/login` 和受保护导航。 |
| F10 | Registry / Job / Artifact / Review / Memory 基础 API | 实现空地基核心 API 和审计边界。 |
| F11 | 假测试模块闭环 | 用非真实业务模块验证 Job、Event、Artifact、Review、Memory 和日志链路。 |
| F12 | n8n 测试 Webhook 闭环 | 仅以测试 Webhook 验证调用、callback、成功和失败回写。 |
| F13 | 空地基验收与封板 | 对照蓝图完成可复现验收，确认生产系统未被修改。 |

## 3. 顺序约束

- 默认按 F04 至 F13 顺序施工。
- 前一任务未通过验收时，不得用后一任务掩盖缺口。
- 每个任务只完成其名称和明确边界内的工作，不得跨任务顺手实现功能。
- F13 完成前不得接入真实业务模块、真实 P 系列或真实 WooCommerce 写操作。
- n8n、Filebrowser、MinIO 和白苏婉生产容器始终位于空地基施工边界之外。

## 4. 引用示例

正确：`F08：认证基础`、`F12：n8n 测试 Webhook 闭环`。

禁止：只写“任务 8”“下一任务”“做登录那个任务”。
