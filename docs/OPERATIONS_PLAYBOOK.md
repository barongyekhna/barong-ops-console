# Barong Yekhna 运营作战手册 v1.0

> 制定日期：2026-07-11
> 适用范围：R 系列选品 → 独立站/亚马逊运营 → 备货 → 开模 全链路
> 核心原则：**任何一步失败，代价都必须被提前锁死。**

---

## 〇、战略总纲（一页看懂）

**打法一句话：用零库存的方式做类目组合投资，把"单品赌博"变成"类目做市"。**

- 不预测哪个产品是爆款——一个大类目铺 20~30 个自发货 SKU，让市场数据把爆款自己顶出来；
- 锚点产品先经选品机器全链验证（利润硬门 + 竞争分析 + GPT 终审），等于先拿到"类目需求存在性证明"再进场；
- 四层风险阶梯逐级放大，每层只用上一层赚到的钱和数据：
  **① 自动抓取选品（零风险）→ ② 自发货海量试验（风险=广告费）→ ③ 胜者备货 FBA/海外仓（风险=小批量库存）→ ④ 爆款开模差异化（风险=模具费，有数据闸门）**
- 前半程（海量铺货）只是**探测器**，真正的猎物是"值得开模建壁垒的那一个"。探测阶段赚的钱都是顺带的，绝不恋战。

## 一、站点架构与品牌

### 1.1 定位

- 主站 = **品类精选站**（多大类目并存），品牌叙事为"严选/懂产品"，不凹"专注单一领域"人设；
- 流量是着陆页级的：SEO/广告访客只看到自己搜索的类目，多类目不会产生杂货店感；
- 站群分离两年内不考虑（SKU > 200 且跑出稳定类目后再议）。

### 1.2 杂货感的三个真实管控点

1. **导航栏/首页**：类目树两级收纳（大类目一级、叶子二级），首页按大类目分区；
2. **品牌叙事**：统一"严选"人设，装得下无限类目；
3. **EDM 分层**：邮件列表按大类目打标，露营买家只收露营内容（n8n 实现）。

### 1.3 SEO 站点结构 = Hub-Spoke 主题权威模型

```
大类目 Hub 页（如：露营）
 ├─ 叶子类目页（帐篷 / 炊具 / 便携淋浴 / 露营工具 / 照明…）
 │   └─ 每叶 3~5 个产品页
 └─ 内容页（来自 Serper「大家也在问」的问题 → 买家指南/博客）
     全部内链成树
```

- Google 排名逻辑吃"主题覆盖完整性"，此结构对 Google 的信号是"这个站在该领域是认真的"；
- 叶子类目之间产品互补不内耗，受众同源，广告与邮件可复用。

## 二、上品规则

| 规则 | 数值 |
|---|---|
| 每个叶子类目 SKU 数 | 3~5 个 |
| 每个大类目叶子数 | 5~6 个 |
| 每个大类目总 SKU | ≈ 20~30 个 |
| 任何时刻活跃大类目（广告层面） | **≤ 2 个，严格串行进场** |
| 月新增 SKU 上限 | ≤ 50 个 |

- **限速器是广告预算和售后带宽，永远不是上架产能**（产能过剩是最危险的诱惑）；
- 大类目 SEO 可适度并行铺（内容边际成本近零），**广告严格串行**：第一大类目数据清晰（正毛利或明确判死）后，第二大类目广告才进场；
- **第一个大类目由数据选**：看 R 系统分组池中锚点密度最高的大类目（哪个类目验证通过的锚点最多 = 需求最密），不拍脑袋。

### 上品流程（全自动链）

1. 分组池选定类目锚点 → 点「1688 扩品」→ AI 精选 10~20 个同类目优质款（主推/跑量/试款分角色）；
2. 每个叶子类目从精选池挑 3~5 款；
3. K 系列（关键词自动带入）→ I 系列作图 → P 系列上架 WooCommerce，一周内全类目上完。

## 三、推广手册

### 3.1 渠道优先级与触发条件

| 顺位 | 渠道 | 何时启用 | 说明 |
|---|---|---|---|
| 1 | **Google Shopping / PMax** | 第一类目上架即开 | 意图流量、feed 驱动无需素材、冷启动性价比最高 |
| 2 | **SEO（hub-spoke + 内容）** | 第一天就铺 | 复利资产；40% 毛利产品的主场 |
| 3 | **EDM（n8n 现成）** | 第一单开始 | 弃购挽回 + 复购流 + 按大类目分层，免费增量 |
| 4 | Google 搜索词广告 | Google Ads API 过审 + 关键词数据到位后 | 精打头部词 |
| 5 | FB / TikTok | dtc_ad 分组出现"3 秒钩子"型产品且毛利 ≥60% 时 | 在此之前一分不花 |

### 3.2 PMax 广告结构（把叶子思路翻译成正确姿势）

```
一个大类目 = 一个 PMax Campaign（预算统一控制在这层）
  每个叶子类目 = 一个 Asset Group
  产品 feed 用 custom_label 打「大类目 + 叶子类目」标签（GMC 工作流打标）
```

- 算法在叶子之间自动调配预算，避免碎片化，学习期只熬一次；
- 跑两周即可在报表看到"哪个叶子在吃单"；
- 表现最好的叶子拆出独立 campaign 加注。

### 3.3 预算与停损

- 单大类目预算：**$30~50/天，集中不分散**；
- 数据周期：跑满 2~3 周才做判断；
- 每周淘汰垫底 1/3 产品，预算向头部集中；
- **停损线：单大类目烧满 $500 广告费零转化 → 类目判死，换锚点，不恋战不加注**；
- 月度广告总预算上限提前定死，盈利前绝不追加（数字待定 → 需老板拍板）。

### 3.4 SEO 时间线的诚实预期

- 新站类目 SEO 见效 3~6 个月起步；
- 它是明年的护城河，**不是本季度的饭**——前 90 天订单与现金流几乎全部来自 Shopping 广告，做预算预测时不得把 SEO 流量算入。

## 四、定价规则

- 试验期定价 = **到岸成本 × 3~4**；
- 理由：留出广告空间 + 未来 FBA 转化空间；
- **禁止低价冲量**：低价吸引价格敏感客，转化数据全部失真，且焊死未来定价空间。

---

## 五、渠道红线（永不做清单)

1. ❌ **亚马逊自发货海量铺货——永久红线**（账号绩效指标 ODR/迟发率不可承受，账号是不可再生资产）；
2. ❌ 亚马逊只上从独立站数据里胜出、走 FBA 的品；
3. ❌ 盈利前追加广告预算；
4. ❌ 备货动用本金（只用利润滚）；
5. ❌ 未经数据闸门开模（见第六节）；
6. ❌ 同时 >2 个大类目打广告；
7. ❌ 探测阶段恋战（分销池是公共池塘，同质化产品必然价格战，护城河在后半程）。

---

## 六、放大路径与开模闸门

### 6.1 胜者放大三步（第 6~12 周起）

头部品判定标准：看**转化率 + 加购率**（不只看销量）。

1. **海外仓自发货提速**：头部品转海外仓，时效 15 天 → 3 天，转化率立涨（最便宜的放大）；
2. **亚马逊 FBA 小批量**：首批 200~300 件，listing 关键词用 R 系统抓好的亚马逊词；
3. **广告加注 + SEO 内容集中**倾斜给胜者。

### 6.2 开模数据闸门（三条全满足才进打样）

1. 连续 **8~12 周**稳定动销；
2. 毛利持续达标；
3. 差评中存在**明确的可改进缺口**（"活儿砌"的差异化空间）。

> 开模由数据触发，不由手痒触发。这条闸门是为"再没找到第二个 camping shower"的执念设的保险丝。

## 七、90 天作战日历

### 第 0~2 周：地基期（1688 审核窗口期）
- 机器：巡库全速攒分组池；
- 老板：每天 10 分钟滑待滑堆 + 翻分组；圈出第一大类目（锚点密度数据辅助）；
- 铺 hub-spoke 内容架构；**零推广支出**。

### 第 2~6 周：第一大类目战役
- 扩品 → 各叶子 3~5 品 → 一周上完 ~25 SKU；
- PMax 单 campaign $30~50/天 + SEO 内容同步；
- 每周砍垫底 1/3；$500 零单即判死。

### 第 6~12 周：胜者放大 + 第二类目进场
- 头部品：海外仓提速 → FBA 小批量；
- 第二大类目广告进场（SEO 可提前铺）；
- 表现数据回灌选品/扩品 AI（反馈环）。
