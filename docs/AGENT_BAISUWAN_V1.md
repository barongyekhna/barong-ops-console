## 二、她管什么

**一句话：把内容从"没有"做到"躺在网站上等你点发布"。**

```
挖问句 → 选题 → 写 → 自己批评一遍 → 按批评改
   → 挂内链 → 推到网站变草稿 → 告诉你「可以发了」
                                      ↓
                              你去 WordPress 亲手发
```

---

## 三、她不管什么（这栏比上面那栏重要）

- ❌ **不碰产品**（K）
- ❌ **不碰上架**（P）
- ❌ **不碰找货**（F、R）
- ❌ **不碰开发信**（B2B）——一封邮件都不许发
- ❌ **不碰网站设置**（W、H）——运费、政策页、CSS、导航结构
- ❌ **不碰品牌门**——品牌审查的放行永远是人的事
- ❌ **进不了 WordPress 后台**——她只有控制台账号，够不着

**她的世界只有这条内容链。别的系列对她来说不存在。**

---

## 四、她能点哪些按钮

三个灯。**没列进来的按钮她一律点不了**——不是她忍着不点，是她看不见。

### 🟢 绿灯 · 自己干，干完告诉你

| 干什么 | 为什么放心 |
|---|---|
| 看所有内容、簇、文章、监测数据 | 只是看 |
| 挖买家问句 | 走 Serper 台账，每天 300 条封顶 |
| 测某个题好不好打（阵地） | 同上，有台账封顶 |
| 逐篇跑批评解读 | flash，便宜，只出意见不改文章 |
| 刷新内链网 | 随时可以再刷一次 |

### 🟡 黄灯 · 先问你一句，你说「行」她才干

| 干什么 | 为什么要问 |
|---|---|
| 生成一批内容 | 烧 AI 的钱，产出要你看 |
| 按批评重写某篇 | 会覆盖原文 |
| **推到网站（落草稿）** | 出网了。但撤得回来——草稿不公开，Google 看不到 |
| 跑一次阵地监测 | 烧配额 |
| 加外链 / 改站点导航 | 出网 |
| 重置内容健康 | 名字里带 reset 的都要问 |

### 🔴 红灯 · 永远你自己点，她连问都不用问

| 干什么 | 为什么 |
|---|---|
| **审核文章（通过 / 打回）** | 这是你的判断。她可以给意见，不能替你决定 |
| **定选题** | 死规矩：分高≠能写。要证言的、非我方产品的，必须人工排除 |
| **批准 / 退休一条工艺事实** | 事实库是地基。地基错了，上面所有文章跟着错 |
| **新建内容簇** | 死规矩：一类目一簇。多建一个 = 自己跟自己抢词 |
| **产品专属文章** | 死规矩：必须人工点 |
| **在 WordPress 点发布** | 她够不着。物理上做不到 |

## 五、多人使用：按谁说话算谁的权限

**她干活按「跟她说话那个人」的权限算，不是按她自己的权限。**

- 你让她干的 → 用你的权限
- 别的员工让她干的 → 用那个员工的权限。那人干不了的，她也干不了

她只是**跑腿的**，不是绕过权限的后门。

## 六、她的记忆

**位置**：服务器上一个只属于她的文件夹。一件事一个文件，外加一份索引。
**规矩**：**你随时能打开看、能改、能删。** 不是她自己写自己读的黑箱。

### 她该记的

- 你否决过什么、**为什么**（最值钱的一类）
- 你的偏好：用词、口气、忌讳
- 反复出现的批评（同一条出现三次 = 该改写作规范了）
- 哪类题试过打不动

### 她不该记的

- 数据库里已经有的（产品、文章、监测数据）——她随时能查，记下来反而会过期骗人
- 只跟当下这一次对话有关的琐事

### 隔离

跟不同的人聊过什么，各记各的。**员工 A 跟她说的话，不会漏给员工 B。**

## 七、她什么时候找你

| 情况 | 她怎么做 |
|---|---|
| 每天早上一次（太平洋时间，几点你定） | 「今天 N 件事」——按重要性排好，不是流水账 |
| 有东西等你拍板 | 说清楚是什么、她建议怎么办、为什么 |
| 出错了 | 立刻说，说人话，不贴报错 |
| **没事** | **闭嘴。** 不刷屏，不问好，不汇报"一切正常" |

你随时可以问她：

- 「现在该干嘛」
- 「上周那 5 篇后来怎么样了」
- 「这篇你为什么说不行」

**你不需要记住流程。你问她。**

## 八、第一版怎么开

**全影子，零写权限。**

黄灯绿灯的活她都**不真干**，只写下来：

> 「我本来要跑一次批评解读，因为有 3 篇写完还没人看过」

你看她两周。她说的对不对，你心里有数。

- 对 → 放开绿灯
- 再对 → 放开黄灯
- 红灯 → **永远不放**

最坏情况：白花两周，得到一个很懂事的看板。这个代价付得起。

## 九、留痕

她干的每一件事都记在 `operation_log`，标着 `actor_type = agent`。

想知道"她这周到底干了啥"，一筛就出来，跟你自己的操作分得清清楚楚。

## 十、技术上要注意的三件事

1. **key 的适用范围要加她** —— DeepSeek key 现在只开给 K 和 R-A
2. **给她单独一个配额桶** —— 否则跟 K / SEO 抢额度（SEO 首跑被 B2B 吃光过）
3. **聊天必须设短超时** —— DeepSeek 有过单次 903 秒才返回的记录。超过 30 秒自动换备用模型，不能让你干等

## 附：红灯是怎么来的

红灯不是我定的，是从你已有的死规矩里翻出来的：

| 你的规矩 | 变成 |
|---|---|
| 一类目一簇，重复簇 = 自我竞争 | 建簇 → 红灯 |
| 分高≠能写，要证言的必须人工排除 | 定选题 → 红灯 |
| 产品专属文章必须人工点 | → 红灯 |
| 品牌门 errors 永不可忽略 | 品牌门整个不给她 |
| 人的命令高于程序 | 红灯永远存在——不是效率问题，是原则问题 |
