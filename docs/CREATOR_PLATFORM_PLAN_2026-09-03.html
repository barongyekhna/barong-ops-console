SECTION 01项目定义

一句话

为有粉丝但做不了硬货的创作者提供"预售即生产"的实体产品代工。创作者出粉丝和预售,你出工厂、AI 前台和认证;双方零库存。

为什么是它:资产正好压在缺口上

你手里的资产市场上的缺口结论
吉林工厂:无固定品类,组装 + 外协整合创作者做不了硬货:MOQ 太高、不会找供应链、不会认证。印花 T 恤谁都能做,户外/锂电/小家电没人给他们小批量做"无固定品类"从劣势变成核心:你不是台灯厂,你是底盘平台
控制台:R 选品 / F 找件 / K 规格出图 / P 上架 / GEO·SEO 内容 / B2B 开发信 / C19 数字员工创作者需要一个从"想法"到"到货"全程有人管的后台八成功能已经存在,过去两年等于在给这个平台造引擎
人在洛杉矶创作者密度最高的城市前三个客户面对面谈
被亚马逊伤过的四点:压货 / 费用 / 封号 / 认证创作者更过不了这四关伤口变成产品:预售零库存、自有渠道、认证产品化
2027 影像工作室计划每个创作者产品都要一支发布片工作室成为本线的发布部门,不是另一个方向

被否决的方向与理由

  • 机器人触觉神经:材料 + 传感器研发,收入前先烧五到十年,买家是整机厂且多自研;和你的任何资产不沾边。起点到终点之间没有一个能活下来的中间态。
  • 把控制台当 SaaS 卖给中国卖家:付费意愿低,没有护城河,竞争者众。
  • 面向粉丝的 App / 平台:粉丝在 Instagram、TikTok、YouTube、抖音上,一个都不在你这;"先造流量再卖货"是独立站 App 没人装的同一个坑。
形状

头两年它就是渠道拓展:创作者是带着粉丝来的分销商,工厂多了一批不压货的美国客户。平台梦碎了,也剩一门赚钱的生意。这是"输了也不亏"的起点,天花板是平台上市。好的十年计划第一年看起来像在解决眼前的事。

SECTION 02商业模式

价值链与钱流

创作者带想法来 / R 系列推选题→AI 前台出方案:底盘选型 · 定制项 · 成本 · 交期 · 认证清单→创作者开 14 天预售(托管预售页)→达标才生产;不达标退款取消→50% 定金 · 工厂开工→品控门 · 认证 · 海运→尾款 · 发货到美国三方仓 / 代发→数字员工全程跟单

三方各拿什么:粉丝拿到一个他信任的人"设计"的真产品;创作者拿到 40% 以上毛利、零库存、一支发布片;你拿到产品毛利、项目服务费,以及一个案例。

层收什么什么时候有说明

第一年 20 个这种项目,收入十几万美元,一个人够活;更重要的是攒下 20 个案例、2–3 个底盘、一套认证库。

零库存是机制,不是口号

  • 预售未达标不生产:达标线 = 底盘 MOQ 底线。没达标,粉丝退款,你损失的是报价时间,那是 AI 干的。
  • 定金在开工前:50% 定金到账才下生产单;发货前收尾款。
  • 底盘限制变量:创作者定制的是外观、颜色、功能组合、品牌;结构件、电池、电路不动。
  • 粉丝对创作者、创作者对你:两段合同,两段账期,你永远不直接对粉丝承担售后(第三年收银台归你之后再重新设计)。

对创作者也一样:他不囤货,这是他从没被人给过的条件。印花代工只给他 15–25% 毛利,你给 40% 以上,还带发布片。

底盘与认证是护城河

底盘:一个验证过、已认证的功能平台,例如"12V 锂电 + 防水壳 + 功能模块"。露营淋浴那套防水锂电工艺是第一个底盘,上面可以长出淋浴、水泵、灯、风扇、加热垫。底盘做到三件事同时成立:交期从 90 天压到 3–4 周;质量事故风险最低;认证一次多客户摊。

认证:一个底盘做一次电池与安全认证,之后每个客户的变体只做差异部分,你的报价永远比新入场者低一截,而且他们连该做哪些认证都不知道。这块直接复用 SEO 模块的工艺事实库结构:哪种工艺配哪种认证,带版本带引用。

为什么抄不了:阿里 Accio 只寻源不生产;Pietra 是供应商目录,不控制交付,估值卡在 2021 年;Printful 只会印花。三家都没有"AI 前台 + 自家工厂 + 认证库"这个组合。等外协厂接进来形成供给侧网络,就是 Xometry 的路。

三条分界线(第三年以后才碰)

  1. 收银台归不归你。预售款经你的手,你就从代工厂变成平台,抽成才有,GMV 才算你的。不经手,永远是供货商。
  2. 供给侧有没有别人的工厂。只有吉林一家,天花板就是一家厂的产能。
  3. 底盘和认证库是不是别人也能用。只给自己用是工厂资产,开放给网络里的厂用才是平台资产。
三句真话
  • 上市路上一定要接受别人进来。融资就意味着董事会和分权。头两三年可以真的一个人;如果底线是永远不交出位置,目标就该改成年入几百万美元的一人公司,也很好,只是不上市。这个决定第三年再做。
  • 硬货交期 60–120 天,创作者等不起。解法就是底盘:交期压到三四周。
  • 中美关税是最大外部风险。前五年不用管,合同里留关税转嫁条款;五年后要第二个组装点。

达人面的五个界面

  1. 我的项目:每个项目一张卡,当前阶段、下一步谁动、截止日。
  2. 报价与方案:底盘、定制项、单价、服务费、交期、认证清单;一键"接受报价"。
  3. 预售实时数:已售 / 目标 / 剩余天数;达标提示;预售页链接与二维码。
  4. 生产进度与品控:阶段时间线(开工 / 组装 / 品控 / 认证 / 装柜 / 海运 / 到仓),每阶段带工厂实拍照片;创作者可以对照片"确认"或"提问"。
  5. 消息:与跟单员(数字员工)的对话;付款提醒;文件(合同、发票、认证报告)。

壳还是原生

创作者感觉不到"套壳"。他看到的是 App Store 搜得到、图标在桌面上、品控照片一到手机就震、分享弹的是系统面板。Shopify 的商家 App、Discord 的 iOS 端用的是 React Native,没人觉得不正式。正式感来自设计、图标、推送和稳定,不来自代码是不是 Swift。

路线代码份数每个功能写几遍适合
控制台模块 + PWA/Capacitor 壳11表单、数字、照片、聊天(本 App 全部内容)
控制台模块 + Swift + Kotlin33AR、离线地图、重渲染(本 App 一个都没有)

苹果审核条款 4.2 会拒"只是把网站装进 App"的壳。避开的办法是壳里有真正的原生能力:推送、相机上传品控反馈、系统分享、离线看进度。这四样恰好是创作者真要的,不是为过审硬加的。苹果开发者账号还在等,原生和壳都卡这道门,所以这个决定不影响进度。建议先按壳走,第三年达人面成重心、要堆手机专属功能时再重写原生,那时重写的钱相对生意是零头。

待拍板 #2:达人面是否接受"PWA → Capacitor 壳"路线。你 08-28 对购物 App 明确要过"不是套壳";达人面是另一个 App,需要你单独拍板。

SECTION 06技术架构与实施

原则:一个引擎两条线。新线是控制台里一个可复用模块,不是给第一个创作者定制的页面;不 fork 现有 B2B 表,复用它的引擎(筛选、模板、抑制名单、邮箱查找)。所有路径与文件名均为本仓库当前真实位置。

模块注册

在 backend/app/core/modules.py 按 b2b.wholesale(约第 1411 行)那条清单的格式新增一条:

module_key="cp.creator_drops"
display_name="达人合作"
category="b2b"                      # 与批发同组,侧边栏同一分区
route_namespace="/creator-drops"    # 前端页面前缀
api_namespace="/creator"            # 后端 /api/app/creator/*
required_permissions=("cp.creator_drops.read",)
permission_manifest: cp.creator_drops.read / .manage / .approve(risk_level="high", 放行定金、放行生产)
feature_flag_key="modules.cp.creator_drops"
data_boundary: reads=(cp_*, k_product_knowledge_products, mfg_items, b2b_email_templates)
               writes=(cp_*, p_notifications)
external_dependencies=("stripe", "serper", "outbound_mailer")

三处必做,漏一处就"隐身"(以前踩过):

  • 侧边栏前缀白名单:frontend/src/components/capability-sidebar-engine.tsx 的 ORGANIZATION_MODULE_PREFIXES 加 cp.;导航项在 frontend/src/lib/navigation.ts。
  • 前端代理白名单:frontend/src/app/api/backend/[...path]/route.ts。/api/app/creator/* 走应用前缀;预售页与达人门户走 /api/public/*,必须逐条登记到 ALLOWED_PUBLIC_GET_PATHS / ALLOWED_PUBLIC_POST_PATHS(公共前缀是精确路径集合,不是前缀匹配)。
  • 组织上下文:模块数据挂在工厂组织下;操作它的真人账号必须恰好有一条 org_memberships(多一条即 403)。创作者不建控制台账号,见 6.4。

项目状态机

  • 报价之前另有一段设计分支(一档/二档/三档),见 8B。
  • 每次跃迁写 timeline_json[status] = 时间戳,并写操作日志(approve 类动作走 operation_log_required)。

达人门户与鉴权

创作者不走控制台账号体系。原因:控制台的组织上下文中间件只在成员关系恰好一条时放行,权限体系为内部员工设计,把外部人塞进去既危险又麻烦。

  • 门户端点挂在 /api/public/creator-portal/*,不经组织上下文中间件(与 auth/login 同前缀策略)。
  • 鉴权 = 每个创作者一把门户钥匙(magic link):邮件里的链接携带一次性 token,换取 30 天有效的门户会话;钥匙哈希存 cp_portal_tokens,可停用、可重发。做法照 MCP 个人钥匙。
  • 门户只能读写自己 creator_id 下的项目;每个端点用 creator 作用域查询,禁止裸 project_id 查表(GEO/SEO 曾经的 workspace_key 泄漏类问题,逐端点 curl 复验)。
  • 速率限制复用 backend/app/modules/c19/rate_limit.py 的做法。
  • 前端页面在 frontend/src/app/portal/*(与 privacy、support 同级,不在 (console) 分组内),独立布局,手机优先。

预售页与收款

  • 页面 frontend/src/app/drop/[slug]/page.tsx,服务端渲染,含产品图(K 出图)、故事、规格、FAQ、倒计时、进度条;结构化数据与品牌硬门沿用现有插件规则(品牌只有创作者品牌 + 制造方署名,不写 30 天退货窗口那类承诺)。
  • 后端 GET /api/public/drops/{slug}、POST /api/public/drops/{slug}/checkout(创建 Stripe Checkout Session,回跳)、POST /api/public/stripe/webhook(签名校验,幂等写 cp_presale_orders)。
  • 第一年:checkout_mode = creator_stripe。用 Stripe Connect(Standard)把页面上的收款直接落到创作者自己的 Stripe 账户,钱不经你手;创作者按合同电汇你定金与尾款。这与现有 B2B 铁律一致:对企业客户只收电汇,不碰信用卡/PayPal。也允许 external_link:创作者用自己的 Shopify,页面只当落地页。
  • 第三年:checkout_mode = platform_stripe,钱进你的平台账户,按 application_fee 抽成后结算给创作者。前置:美国主体、Stripe 平台账户、产品责任险、销售税(用 Stripe Tax)。
  • Stripe 密钥进现有密钥管理与 key-health 巡检;每一笔出网付费调用当天接台账(Serper 事件的铁律)。

前期不是"推广",是"找 10 个人"。第一年的客户是 10–30 个创作者,是一份名单,不是市场。对一份名单,广告、SEO、社媒运营全是错误工具;Google 烧掉 500 美金那次就是拿市场工具去做名单的事。

定价公式

到岸供货价 = (BOM + 组装工时 + 品控 + 包装) × (1 + 加成 25%–35%)
             + 单件运费分摊 + 单件关税分摊
项目服务费 = 设计/打样实际成本 + 认证差异项实际费用 + 20% 管理费
预售达标线 = max(底盘 MOQ 底线, 覆盖固定成本所需件数)
定金       = 预售达标后合同总额 × 50%,开工前到账
尾款       = 其余 50%,发运前到账
  • 报价对创作者展示三行:单价、服务费、达标线。成本明细不给。
  • 合同币种美元;收款电汇;汇率风险写进合同(报价有效期 30 天)。

合同关键条款(给律师的清单,不是合同)

  • 预售未达标自动终止,双方无违约;创作者负责退款给粉丝(第一年模式)。
  • 定金不退;尾款未付不发运;超期 30 天未付尾款,货物按合同处置。
  • 知识产权:创作者的 logo / 品牌归创作者;底盘、结构、电路、认证归你;创作者不得把底盘拿给别的厂做。
  • 品质:以品控报告 + 认证报告为验收依据;不良率上限与补发规则。
  • 产品责任:美国销售方(创作者或其公司)购买产品责任险;你提供认证与技术文件。第三年收银台归你之后,责任险由你买。
  • 关税与政策变化转嫁条款;不可抗力。
  • 案例授权:允许你以"为 X 制造"作为案例展示(可选退出)。

SECTION 08B设计谁来做

REV 1 漏掉的洞

"底盘"只回答了底盘之内的事。创作者提的想法一半在底盘之外,图纸、规格书、模具谁来出,REV 1 一个字没写。答案不是"你做"也不是"创作者做",而是把设计分成三档,每档主人不同。

档是什么谁做周期费用第一年接不接
一档 · 底盘之内颜色、logo、模块组合;配置器里选没有设计这件事,设计在建底盘时做完00接,目标占八成
二档 · 公模整合底盘之外但公模件齐全:车架/电机/电调/泵/电池/PCBA 全是现成件,只新做外壳或一个结构件你 + AI(F 系列找件拼 BOM)+ 一位外包工业设计师画外壳2–4 周设计;小批量硅胶覆膜 / 3D 打印,大批量开钢模ID 几千到两万人民币;软模几千,钢模几万到十几万接;这是工厂"组装 + 外协整合"模式的主场
三档 · 从零工业设计 + 结构 + 电路 + 固件 + DFM 整套设计外包:深圳/东莞的工业设计公司 + 方案公司(PCBA 带固件)+ 结构公司(模具图);他们是你的供应商,创作者看不见6–12 周几万到十几万人民币只接创作者预付设计费的

以遥控车为例

  • 车架、电机、电调、接收机、电池:1688 现成件,规格书由元件厂提供;安装接口尺寸由公模厂提供图纸。
  • 唯一要新画的是车壳:外包工业设计师在公模安装接口之上建模,两三周;小批量硅胶覆膜,过量后开钢模。
  • 所以遥控车是二档,不是三档。世界上八成的"创作者产品"都是公模改外观。

创作者去哪做设计:哪也不去

他只需要说清楚想要什么,而这正是真正的瓶颈。他会说"一个很酷的越野遥控车",设计师没法拿这句话报价。AI 前台的核心工作是把一句模糊的话追问成一份需求规格书(PRD):用途与玩法、尺寸与重量、性能(速度/续航/防水等级)、价格带、参考产品与"必须有 / 不能有"、品牌资产。规格书生成后自动分档:一档进配置器;二档走 F 找件 + 一位外壳设计师;三档去设计公司询价。

AI 能做与不能做(2026 现状,别信宣传)

  • 能:写需求规格书;从 1688 规格拼 BOM 与成本;出概念渲染图(K 管线);比对元件规格是否匹配(电压/电流/尺寸)。
  • 不能:能上机床的图纸、公差配合、模具分型、DFM。这些仍由人做。AI CAD 类工具可以出草模给设计师起步,不能替代设计师交付。
写死的规矩
  • 三档设计费创作者预付,永远不从预售款里出。设计发生在预售之前,预售还没有钱;愿不愿付设计费是筛掉不认真的人最好的过滤器。
  • 设计成果的归属写进合同:外观归创作者,结构/电路/模具归你(并计入底盘库,下一个客户可复用)。
  • 二档的外壳设计师与三档的设计公司都是供应商,进供应商表、有交期与质量记录,与电机供应商同等管理。

对数据模型与状态机的补充

  • 新表 cp_design_briefs:project_id, tier(1/2/3), prd_json(AI 生成的需求规格书,人工确认版本), reference_urls, must_have / must_not, approved_at。
  • 新表 cp_design_vendors:name, kind(id / structure / pcba_solution / mold), city, contact, lead_days_typical, quality_score, projects_done。
  • cp_projects 加 design_tier 与 design_fee_usd;cp_payments.kind 加 design_fee。
  • 状态机在 inquiry 与 quoted 之间加分支:brief_drafted → brief_approved → (tier 1 直接报价 | tier 2 design_in_progress → design_done | tier 3 design_fee_paid → design_in_progress → design_done)。设计费未到账,三档项目卡在 brief_approved 不动。
  • 每个二三档项目完成后,把新做的结构件与认证登记进 cp_base_platforms,底盘库随项目自然长大。
